# Plan de Migración de Datos
## Proyecto: Plataforma Web Tecnomatic MAV (Dotaciones y Seguridad Industrial)
**Código Documental:** 02.3_MIG | **Enfoque:** Guía de Migración de Datos (SENA CEET)  
**Versión:** 1.0 (Resumida y Práctica)  

---

## 1. ¿Cuál es el Objetivo de este Plan?
Pasar toda la información que hoy está dispersa en **archivos de Excel y notas de papel** hacia la nueva base de datos del sistema web (**MySQL / Supabase**), garantizando que ningún dato se pierda, que no haya información duplicada y que la operación de la empresa no se detenga.

---

## 2. ¿Qué Datos se Migran y en qué Orden? (Inventario de Carga)

Para no romper las relaciones de la base de datos (claves foráneas), los datos deben subirse en un orden estricto de **4 niveles**:

```
[Nivel 1: Datos Maestros]  --> Clientes y Productos (No dependen de nadie)
          ↓
[Nivel 2: Transaccionales] --> Facturas y Pedidos (Necesitan que existan Clientes y Productos)
          ↓
[Nivel 3: Pagos y Abonos]  --> Recibos de Pago (Necesitan que existan Facturas)
          ↓
[Nivel 4: Conteo Final]    --> Ajuste de Stock real en bodega
```

### Tabla de Datos a Migrar:

| Orden | Entidad / Tabla | Origen Actual | ¿De quién depende? | Volumen Estimado |
| :---: | :--- | :--- | :--- | :---: |
| **1°** | **Clientes** | Hojas de Excel y libretas | Ninguno (Independiente) | ~250 empresas |
| **2°** | **Catálogo y Productos EPP** | Listas de precios en Excel | Ninguno (Independiente) | ~120 productos |
| **3°** | **Variantes (Tallas y Colores)**| Notas de bodega | Del producto principal | ~450 variantes |
| **4°** | **Facturas y Pedidos Históricos**| Facturas físicas en papel | Del cliente y del producto | ~1.200 registros |
| **5°** | **Pagos y Recibos** | Talonarios de caja | De la factura correspondiente | ~1.000 abonos |
| **6°** | **Stock Inicial** | Conteo físico en bodega | De la variante del producto | Inventario inicial |

> **Regla de oro:** Lo que no esté en este inventario o tenga más de 3 años de antigüedad sin movimiento, **no se migra** para no llenar el nuevo sistema con datos basura.

---

## 3. Estrategia de Migración y Entornos

### Estrategia Elegida: "Big Bang" Controlado
* **¿Cómo funciona?:** Toda la información se migra de una sola vez durante una **ventana de mantenimiento** de fin de semana (sábado en la noche o domingo), cuando la empresa no está atendiendo ventas.
* **¿Por qué se eligió?:** Porque el volumen de datos de Tecnomatic MAV es mediano (menos de 5.000 registros totales), lo que permite hacer la carga completa en menos de **3 horas**.

### Los 2 Ambientes de Trabajo:
1. **Ambiente de Pruebas (Staging):** Aquí se prueba el script de migración una y otra vez hasta que funcione al 100% sin errores.
2. **Ambiente de Producción:** El sistema real. **Nunca se prueba directamente aquí.** Solo se toca el día del paso definitivo.

---

## 4. Limpieza y Normalización de Datos

Los archivos de Excel traen errores humanos comunes (nombres con tildes raras, espacios dobles, teléfonos incompletos). Antes de subirlos a la base de datos, se limpian automáticamente con un pequeño script en Node.js.

### Reglas de Limpieza Básicas:
1. **Nombres y Razones Sociales:** Se quitan espacios dobles y tildes problemáticas.
2. **Teléfonos:** Se estandarizan al formato celular de Colombia (`+57 3XX XXX XXXX`).
3. **Correos Electrónicos:** Todos se pasan a minúsculas y sin espacios (`cliente@empresa.com`).
4. **Tallas:** Se estandarizan a nombres uniformes (ej: `39`, `40`, `S`, `M`, `L`, `XL`, `UNICA`).

### Ejemplo del Script Limpiador (Node.js):
```javascript
// Función para limpiar nombres y evitar clientes duplicados
const limpiarTexto = (texto) => {
  return String(texto || '')
    .normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '') // Quita tildes
    .replace(/\s+/g, ' ')            // Quita espacios dobles
    .trim()                          // Quita espacios al inicio y final
    .toUpperCase();                  // Todo a mayúsculas uniformes
};
```

## 5. Fases de Ejecución del Plan

El proceso se cumple en **6 fases secuenciales**:

* **Fase 0: Preparación (Días 1 a 3):** Recopilar todos los Excels de clientes y productos. Corregir datos vacíos a mano.
* **Fase 1: Prueba de Maestros (Día 4):** Cargar clientes y productos en el ambiente de pruebas.
* **Fase 2: Prueba Transaccional (Día 5):** Cargar facturas y pagos de prueba comprobando que sumen exactamente igual.
* **Fase 3: Validación con el Usuario (UAT) (Días 6 y 7):** El dueño o administrador de Tecnomatic MAV entra al sistema de pruebas, busca 10 clientes y 10 productos al azar y valida que los precios y datos sean correctos.
* **Fase 4: Día del Corte (Go-Live - Fin de semana):**
  1. Se toma una copia de respaldo completa.
  2. Se ejecuta el script de migración definitivo en producción.
  3. Pruebas de humo (verificar que el sistema inicie y permita crear una venta).
* **Fase 5: Acompañamiento (Primeras 2 semanas):** Soporte técnico prioritario por si algún usuario detecta un dato por corregir.

## 6. ¿Cómo Comprobamos que la Migración fue Exitosa? (Validaciones SQL)

La migración no se aprueba al "ojo"; se aprueba con **3 consultas SQL obligatorias**:

### 1. Que no se haya perdido ninguna fila (Conteo):
```sql
-- Debe dar exactamente la misma cantidad de filas que el archivo Excel origen
SELECT COUNT(*) AS total_clientes_migrados FROM Usuarios WHERE Rol = 'cliente';
SELECT COUNT(*) AS total_productos_migrados FROM Productos;
```

### 2. Que el dinero coincida al centavo (Suma total):
```sql
-- La suma total de ventas históricas debe cuadrar con el balance de caja
SELECT SUM(Total) AS total_facturado_sistema FROM Facturas;
```

### 3. Que no haya datos huérfanos o con errores:
```sql
-- Buscar si hay facturas asignadas a clientes que no existen (debe dar 0)
SELECT * FROM Facturas WHERE Usuarios_idUsuarios NOT IN (SELECT idUsuarios FROM Usuarios);

-- Buscar productos con precio en 0 o negativo (debe dar 0)
SELECT * FROM Productos WHERE Precio <= 0;
```

## 7. Plan de Contingencia y Reversión (Rollback)

¿Qué pasa si el día de la migración algo sale mal (se va la luz, falla la base de datos o faltan datos críticos)?  
**Se aplica el Plan B de inmediato:**

1. **Frenar el acceso:** Se bloquea el acceso temporal a la página para que nadie ingrese ventas incompletas.
2. **Restaurar respaldo:** Se restaura la base de datos desde la copia de seguridad que se sacó 10 minutos antes de empezar.
3. **Continuar operando:** La empresa sigue trabajando con sus hojas de cálculo habituales el lunes por la mañana sin paralizar la atención al cliente.
4. **Diagnóstico:** El equipo de desarrollo revisa el error en el script, lo corrige en pruebas y programa una nueva fecha de corte.
