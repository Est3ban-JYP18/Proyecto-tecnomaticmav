## 1. Resumen Ejecutivo

### 1.1 Descripción General
Tecnomatic MAV es una plataforma web integral diseñada para la comercialización mayorista, cotización formal y control de inventario de dotaciones empresariales y Equipos de Protección Personal (EPP). Centraliza el catálogo comercial con variantes técnicas (tallas, colores, normativas de seguridad), pasarela de pagos digitales, emisión de recibos y facturas, y seguimiento logístico de pedidos.

### 1.2 Ficha Técnica de la Arquitectura
* **Paradigma:** Single Page Application (SPA) reactiva y modular.
* **Arquitectura:** Arquitectura en capas desacopladas (Frontend en React + API RESTful en Node.js/Express + Base de datos Híbrida MySQL/Supabase).
* **Tipo:** Web Application responsiva orientada a la nube.
* **Escalabilidad:** Horizontal para servicios web y modular en endpoints de negocio.

### 1.3 Características Principales del Sistema
* **Catálogo Técnico con Variantes:** Visualización en tiempo real de tallas, colores y existencias disponibles de EPP.
* **Cotizador Corporativo B2B:** Generación y respuesta a solicitudes de cotización por volumen.
* **Checkout Seguro:** Integración con pasarela de pagos Mercado Pago (PSE, tarjetas de crédito y débito).
* **Control de Inventario y Auditoría:** Alertas automáticas por stock mínimo, papelera de reciclaje y registro de cambios en productos.
* **Facturación Digital:** Generación de recibos con numeración consecutiva única y descarga en PDF.

### 1.4 Principios de Diseño
1. **Separación de Responsabilidades (Separation of Concerns):** La interfaz gráfica no accede directamente a la base de datos; toda operación pasa por la API REST validada por middleware.
2. **Seguridad por Diseño (Security by Design):** Control estricto de roles (Admin/Cliente) mediante tokens JWT y cifrado de datos sensibles.
3. **Usabilidad y Rendimiento (Performance First):** Tiempos de carga reducidos (< 2 segundos) y diseño totalmente adaptable a celulares y computadores.

### 2.2 Justificación de Decisiones Técnicas

#### ¿Por qué React 19 + Vite?
1. **Velocidad de Desarrollo:** Vite inicia el servidor de desarrollo en menos de 0.5 segundos gracias a módulos ES nativos, frente a Webpack que demora más de 6 segundos.
2. **Modularidad Basada en Componentes:** Facilita reutilizar componentes clave como tarjetas de producto, botones de cotización y tablas administrativas.
3. **Ecosistema y Rendimiento:** React 19 optimiza el renderizado del DOM virtual y el manejo del estado local.

#### ¿Por qué Node.js/Express + MySQL/Supabase?
* **Flexibilidad y Control:** Express 5 permite controlar middlewares personalizados de seguridad (validación de JWT, roles y CORS) y manejar webhooks asíncronos de pagos.
* **Modelo Híbrido Confiable:** Permite operar localmente con MySQL para entornos de desarrollo y respaldar facturas y recibos en la nube con Supabase.

### 3.3 Flujo de Datos: Proceso de Compra y Checkout

```
1. Usuario añade producto al carrito (Talla, Color, Cantidad)
   ↓
2. El componente Carrito.jsx valida existencia de stock
   ↓
3. Clic en "Pagar con Mercado Pago" → Envia POST /api/crear-preferencia-mp
   ↓
4. server.cjs crea preferencia en Mercado Pago y retorna init_point
   ↓
5. Usuario completa el pago en la pasarela segura
   ↓
6. Webhook / Retorno confirma pago → Descuenta stock en BD y genera recibo
   ↓
7. ReciboModal.jsx muestra el recibo listo para descargar en PDF
```

### 3.4 Rutas Públicas vs. Rutas Protegidas

* **Rutas Públicas:** Inicio (`/home`), Catálogo de Productos, Cotizador Corporativo, Quiénes Somos, Contacto y Login/Registro.
* **Rutas Protegidas (Requieren Token):**
  * Rol Cliente: Historial de Compras (`/mis-pedidos`), Solicitud de Devoluciones.
  * Rol Administrador: Dashboard Gerencial, Gestión de Stock (`/gestion-stock`), Tabla de Usuarios, Auditoría y Aprobación de Cotizaciones.

## 4. Base de Datos

### 4.1 Modelo Entidad-Relación (Tablas Principales)

El sistema utiliza un modelo relacional estructurado en torno a productos, variantes técnicas y documentos comerciales:

```
[Usuarios] 1 ────────── N [Cotizaciones]
    │
    │ 1
    │
    └── N [Facturas / Recibos]
               │
               │ N
               │
               └── 1 [Productos] 1 ── 1 [Producto_Atributos]
                          │
                          │ 1
                          │
                          └── N [Producto_Variantes]
```

### 4.2 Definición de Tablas Principales (DDL SQL)

```sql
-- 1. Tabla de Atributos Técnicos de Seguridad EPP
CREATE TABLE IF NOT EXISTS Producto_Atributos (
  Productos_idProductos INT NOT NULL PRIMARY KEY,
  Marca VARCHAR(100) NULL,
  Material VARCHAR(150) NULL,
  Nivel_Proteccion VARCHAR(150) NULL,
  Stock_Minimo INT NOT NULL DEFAULT 5,
  FOREIGN KEY (Productos_idProductos) REFERENCES Productos(idProductos) ON DELETE CASCADE
);

-- 2. Variantes de Producto (Tallas y Colores con Stock Individual)
CREATE TABLE IF NOT EXISTS Producto_Variantes (
  idProductoVariante INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  Productos_idProductos INT NOT NULL,
  Color VARCHAR(80) NOT NULL DEFAULT 'Único',
  Talla VARCHAR(20) NOT NULL DEFAULT 'Única',
  Imagen VARCHAR(500) NULL,
  Stock INT NOT NULL DEFAULT 0,
  Activa TINYINT(1) NOT NULL DEFAULT 1,
  UNIQUE KEY uq_variante_producto_color_talla (Productos_idProductos, Color, Talla),
  FOREIGN KEY (Productos_idProductos) REFERENCES Productos(idProductos) ON DELETE CASCADE
);

-- 3. Registro de Auditoría de Cambios
CREATE TABLE IF NOT EXISTS Auditoria_Productos (
  idAuditoriaProducto INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  Productos_idProductos INT NOT NULL,
  Usuarios_idUsuarios INT NULL,
  Accion VARCHAR(60) NOT NULL,
  Detalle TEXT NULL,
  Creada_En DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (Productos_idProductos) REFERENCES Productos(idProductos) ON DELETE CASCADE
);

-- 4. Papelera de Reciclaje (Soft Delete)
CREATE TABLE IF NOT EXISTS Productos_Papelera (
  Productos_idProductos INT NOT NULL PRIMARY KEY,
  Eliminado_En DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  Eliminado_Por INT NULL,
  FOREIGN KEY (Productos_idProductos) REFERENCES Productos(idProductos) ON DELETE CASCADE
);
```

### 4.3 Índices para Optimización de Consultas

1. `uq_variante_producto_color_talla`: Índice único compuesto en `Producto_Variantes` para evitar tallas duplicadas y acelerar la consulta de existencias.
2. `idx_facturas_usuario`: Acelera la búsqueda de pedidos históricos cuando un cliente consulta su historial.
3. `idx_productos_categoria`: Optimiza el filtrado del catálogo en la tienda virtual.

### 4.4 Integridad Referencial y Reglas de Eliminación
* **`ON DELETE CASCADE` en Variantes y Atributos:** Si se elimina un producto definitivamente, sus variantes asociadas se borran automáticamente para no dejar huérfanos.
* **`Soft Delete` en Catálogo:** Los productos comerciales no se borran físicamente con `DELETE`; se trasladan a `Productos_Papelera` para preservar el historial de facturas antiguas.

## 5. APIs y Endpoints

La comunicación entre el cliente y el servidor se realiza mediante llamadas HTTP REST con intercambio de cargas JSON.

### 5.1 Catálogo de Endpoints Principales

| Método | Endpoint | Acceso | Descripción |
| :---: | :--- | :---: | :--- |
| `GET` | `/api/productos` | Público | Lista todos los productos activos con sus variantes |
| `POST`| `/api/productos` | Admin | Crea un nuevo producto y sus atributos técnicos |
| `POST`| `/api/cotizaciones`| Cliente | Radica una nueva cotización formal por volumen |
| `GET` | `/api/cotizaciones`| Admin | Consulta solicitudes de cotización pendientes |
| `POST`| `/api/crear-preferencia-mp`| Cliente | Genera sesión de pago en Mercado Pago |
| `POST`| `/api/login` | Público | Autentica credenciales y entrega token JWT |
| `POST`| `/api/recuperar-clave` | Público | Envía código OTP de 6 dígitos por correo |

### 5.2 Ejemplo de Petición y Respuesta

**Petición Frontend (Crear Preferencia de Pago):**
```javascript
const respuesta = await fetch("http://localhost:3000/api/crear-preferencia-mp", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    items: [{ title: "Bota Seguridad Dielectrica", unit_price: 120000, quantity: 2 }]
  })
});
const data = await respuesta.json();
window.location.href = data.init_point; // Redirección a Mercado Pago
```

## 6. Seguridad

### 6.1 Autenticación y Autorización (JWT y RBAC)
* Las contraseñas de los usuarios no se guardan en texto plano.
* Al iniciar sesión con éxito, el servidor genera un token JWT firmado con una clave secreta (`JWT_SECRET`) que almacena el ID del usuario y su rol (`admin` o `cliente`).
* El middleware `verifyToken.js` intercepta cada petición a rutas administrativas y valida el token antes de dar acceso a la base de datos.

### 6.2 Manejo de Variables de Entorno (`.env`)
Los secretos nunca se suben a Git ni se exponen en el navegador. Se protegen en el archivo `.env` del backend:
```env
PORT=3000
DB_HOST=127.0.0.1
DB_USER=root
DB_PASS=******
DB_NAME=tecnomaticmav
JWT_SECRET=super_secreto_tecnomatic_2026
MP_ACCESS_TOKEN=APP_USR-*******
SMTP_PASS=******
```

### 6.3 Protección contra Inyección SQL y XSS
* Se utilizan consultas parametrizadas (`db.query("SELECT * FROM Productos WHERE id = ?", [id])`) provistas por `mysql2`, neutralizando intentos de inyección SQL.
* React previene ataques de Cross-Site Scripting (XSS) al escapar automáticamente los valores insertados en el DOM.

## 7. Rendimiento y Optimización

1. **Compilación Optimizada con Vite:** Al ejecutar `npm run build`, Vite divide el código en bloques modulares (*code-splitting*), generando paquetes estáticos minificados en la carpeta `dist/`.
2. **Debounce en Búsquedas de Catálogo:** Se implementa un temporizador de 300 ms al escribir en el buscador de productos, evitando lanzar peticiones a la base de datos por cada letra presionada.
3. **Carga Eficiente de Imágenes:** Las fotografías de dotaciones se cargan con dimensiones estandarizadas para mantener un consumo ligero de datos móviles.

## 11. Anexos y Cierre

### 11.1 Comandos Frecuentes
* `npm run dev`: Levanta el servidor de desarrollo.
* `npm run build`: Genera el compilado listo para producción en `dist/`.
* `npm run lint`: Ejecuta el análisis estático de código con ESLint.

### 11.2 Glosario Técnico Clave
1. **API REST:** Interfaz que permite al frontend comunicarse con el backend mediante métodos HTTP estándar (GET, POST, PUT, DELETE).
2. **BaaS (Backend as a Service):** Servicios en la nube como Supabase que proporcionan bases de datos y autenticación sin administrar hardware.
3. **CORS:** Mecanismo de seguridad que controla qué dominios web pueden solicitar datos a la API.
4. **HMR (Hot Module Replacement):** Función de Vite que actualiza componentes en el navegador sin recargar toda la página.
5. **JWT (JSON Web Token):** Estándar seguro y compacto para transmitir la identidad de un usuario en encabezados HTTP.
6. **Middleware:** Función intermedia que inspecciona una petición antes de permitirle llegar al controlador final.
7. **ORM / Driver:** Conector (`mysql2`) que permite ejecutar instrucciones SQL desde JavaScript.
8. **PSE:** Plataforma colombiana para pagos bancarios en línea directamente desde la cuenta de ahorros/corriente.
9. **RBAC:** Control de acceso basado en el rol específico asignado a cada usuario.
10. **Soft Delete:** Marcado lógico de un registro para ocultarlo de la interfaz sin borrar su fila en la base de datos.
11. **SPA:** Aplicación web de una sola página que carga una sola vez y navega dinámicamente.
12. **Webhook:** Notificación automática que envía un servicio externo (ej. Mercado Pago) al backend cuando ocurre un evento de pago.
